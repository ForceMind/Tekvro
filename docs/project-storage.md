# Tekvro 项目存储契约

PW-01 的首个实现提供共享应用服务与版本一元数据。入口为
`src/application/project/ProjectStore.ts` 的 `create`、`read`、
`edit`，领域契约在 `src/domain/projectManifest.ts`。
CLI/MCP 项目入口、运行调度与独立检查已经实现，实际用法见[项目运行指南](project-workflow-runtime.md)，验证范围见[验收矩阵](project-workflow-acceptance.md)。工作台仍按后续工作包推进。

## 字段与归属

调用方提供项目名称、调查或重建目标、原始输入表达、目标绝对路径及摘要、
输出根目录和必要要求。存储服务生成稳定 UUID、时间及单调 revision。
名称变化保留项目身份。目标摘要是本次保存的范围输入，后续执行须核对实际制品。

`scope_sha256` 由规范 JSON 摘要生成。`scope_revision` 单独追踪范围变化，
修改范围须记录 `change_reason`。候选摘要与范围摘要分别保存。
历史检查保留候选、范围、检查器、场景、环境和报告身份；
`projectCheckIsCurrent` 判断其范围和候选是否仍与当前选择一致。
ProjectStore 负责保存和验证项目元数据及引用，不打开检查报告或执行检查。当前运行切片已实现外部检查报告的摘要认证与独立检查；项目工作流中的完整 Evidence/bundle 认证、义务账本闭合及项目验收汇总仍待 PW-04 对应验收，范围见[验收矩阵](project-workflow-acceptance.md)。

`phase`、`execution_status` 与 `acceptance_status` 分别保存。
M0 创建的状态为 study、idle、not_evaluated。当前编辑入口只修改范围和引用，
拒绝写入未经检查器工作流产生的 pass/fail。记录了 Evidence ID 或结束执行，
都不会单独产生验收结论。

## 原子提交与并发

项目管理目录须尚不存在，父目录须存在。当前目录内以 16 位十进制序号保存
完整 revision，例如 `0000000000000001.json`。每个文件保存格式名、版本、
完整项目、上一 revision 的摘要及自身摘要。

编辑需提交上次读取的 project_id、revision 和 digest。服务检查当前提交，
通过既有 `writeTextParts` 和 `OwnedStagedOutput` 暂存完整内容，
再以硬链接独占发布下一个序号。同一序号只能发布一次，
竞争失败的写入返回 `ProjectRevisionConflict`，携带期望与当前 token。
读取将符号链接目录解析到同一位置，因此目录别名不会产生另一套并发状态。

此实现用独占 revision 槽实现短事务的比较并提交。运行 Builder 的互斥与资源生命周期
仍由 PW-02 处理。没有以 PID 或文件年龄抢占元数据锁的操作。

读取验证从第一项开始的连续序号、格式、摘要链、项目身份、时间与范围版本。
已提交的损坏文件会阻止读取，原文件保留供诊断。
未发布的暂存内容不会成为新 revision，读取仍返回最后的完整提交；
本服务不会清理无法证明归属的残留文件。首次创建失败后只剩不完整目录时，
读取报告缺少提交，重新创建会拒绝覆盖该目录。

原子发布与掉电持久性分别记录。当前沿用既有文件发布能力，未建立文件系统同步
或网络文件系统的额外保证。没有硬链接能力的文件系统将返回写入失败。
提交成功而暂存清理失败时，既有错误回执保留已发布路径和清理情况；
调用方须先读取当前 revision 后再决定下一步。

## 版本与移动

这是首个持久化版本，没有先前已发布的项目格式可迁移。版本 0、未知新版本、
缺字段及损坏 JSON 均保留原始文件并返回错误。以后增加已知旧版本时，
需补逐版本迁移及源文件保留验证，才能开放对应输入。

项目管理目录可以单独移动。重新读取保留 project_id 和 revision，
返回新的实际元数据位置。显式目标、输出和证据路径继续保留原值；
跨系统或目标路径改变时，应通过有原因记录的范围修订重新绑定，
并在执行前复验宿主和文件身份。

持久化的目标、输出、Evidence 和报告路径按 POSIX/Windows 绝对路径语法保存，
不因读取宿主不同而拒绝历史 revision，也不改写分隔符或驱动器拼写。
创建、读取和编辑元数据不会访问这些引用路径。后续实际使用路径的服务须检查
当前宿主的路径语法与文件身份；可以读取历史记录不代表该路径能在当前机器执行。

## 当前验证

`tests/boundary/filesystem/projectStore.test.ts` 覆盖保存重读、名称变化、
未知版本、损坏提交、序号缺口、未发布暂存、取消、过期 token、
范围与候选变化、元数据移动及两个真实进程通过符号链接别名竞争提交。

本地 Linux x64 / Node.js 24.22.1 共 15 项通过，包含 Windows 驱动器、UNC 及 POSIX
历史路径的保存、移动、重新绑定和历史字节保留。它们是持久化验证，不计为 Windows 实测。
双进程别名场景在 Windows 按环境条件跳过，尚无本实现的 Windows 实测记录。
这些结果验证元数据边界，后续 Agent、浏览器、设备及 CLI/MCP 对等验收
使用各自的工作包记录。
