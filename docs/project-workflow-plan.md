# 项目化分析与重建工作流：实施计划

## 状态与接续基线

本计划为新增研发轨道，目标是把已有分析、证据和比较能力组织为可恢复的项目工作流，并接入编码 Agent 完成构建与修正。**PW-01 至 PW-10 的实现状态均为未开始；本文的提交只完成规划，不表示任何新增功能已经可用。**

规划时核对的主线为 `ee5ebf85b35c800c92d2e308ea601c158c529596`，产品版本为 `1.0.0`。接手实现时必须重新查询实际主线、未合并 PR、审阅意见与 CI；此提交号只标识本计划使用的代码基线。

现有 `environment-build` 生成的是基于捕获的 Agent 环境，并非完整应用生成器。既有重建评价器检查调用者提供的证明，不会自动执行所有声明中的验证命令。新增编排负责补齐实际执行和项目体验，保留这些已有语义。

项目可以承载纯调查目标或重建目标。纯调查项目可以用已保存的分析结论、证据和明确未知项结束，无需启动 Builder；是否满足目标按该项目的需求和证据判定，不能套用重建项目的全部检查项。

首个重建目标是一个本地网页或 H5 样例的完整工作流：研究选定目标、构建新项目、运行独立检查、根据差异修正、输出结果和未验证范围。以普通命令、脚本和共享应用服务组合这些步骤，不引入通用编排语言。桌面应用、游戏、外部服务和实体设备分别记录支持条件。

## 工作包

### PW-01：项目契约与持久化

**状态：未开始。阶段：M0。**

- **目标与范围：** 定义版本化项目清单、调查/重建目标类型、目标与输出根目录、需求范围、证据引用、运行与轮次身份、检查引用和待决事项。执行状态、验收状态、阶段以及可运行事实分别建模，字段语义以[设计方案](project-workflow-design.md)为准。保存明确的 schema 版本及迁移规则，不能默默接受未知版本。
- **源码触点：** 复核 `src/domain/evidence.ts`、`src/domain/evidenceBundle.ts`、`src/domain/analysisSnapshot.ts`、`src/application/binary/AnalysisSnapshotFiles.ts`、`src/application/JsonFiles.ts` 与 `src/filesystem/`。新增项目模块路径在实现 PR 中确定，领域逻辑不得承担文件 I/O。
- **依赖：** 无新增工作包前置；须先检查实际主线和已有未合并变更。
- **验收：** 对应 `PWA-01`、`PWA-11`；验证保存后重读、未知版本与损坏输入拒绝、明确迁移、证据绑定、项目移动/重定位的处理。模拟写入中断后旧记录仍完整；并发写入须报告冲突而非丢失更新。
- **证据与完成标准：** 提交项目 schema、版本策略、持久化实现和边界验证记录；当前提交的检查通过后才能标记完成。项目身份与构建内容身份应能分别定位，旧检查不能证明修改后的新构建。
- **未验边界：** 本包完成不代表编码 Agent 已运行，不证明自动恢复进程或任何重建结果通过。

### PW-02：执行状态、恢复、进展与预算

**状态：未开始。阶段：M1。**

- **目标与范围：** 实现研究、构建、检查、修正、交付的受控执行；保存阶段变化、当前轮次、最后活动、恢复点和未完成清理。区分暂停、进程/连接中断、失败与用户取消；耗尽预算或无进展不能变成验收通过。配置轮次、时间和可观测资源预算，保留具体停止原因。
- **源码触点：** `src/process/OwnedCommand.ts`、`src/process/OwnedLease.ts`、`src/process/ProviderDeadline.ts`、`src/application/AnalysisSettings.ts`、`src/application/closeOwnedWebResources.ts`；新增项目执行服务调用这些归属和清理基础。
- **依赖：** PW-01；与 PW-03/04/06 约定统一运行事件和取消接口。
- **验收：** 对应 `PWA-02`、`PWA-03`、`PWA-06`；验证中断写入、重复恢复、并发运行、无活动诊断、重复输出、预算停止和取消。恢复不得仅凭旧 PID 杀进程，也不能在未确认副作用状态时自动重做构建或检查命令。
- **证据与完成标准：** 保存中断前后项目记录、进程归属与清理结果；重新打开项目后可给出可执行的下一步。无进展判定同时参考构建内容和检查结果，不能把日志心跳当作有效修正。未上报的 token 或费用保持未知，不伪造计量。
- **未验边界：** 进度显示不证明后台进程持续正确工作；恢复成功不自动关闭原有未知项。预算调整和继续执行沿用用户已有授权范围，不新增重复确认字段。

### PW-03：BuilderAdapter 与首个真实编码 Agent

**状态：未开始。阶段：M1。**

- **目标与范围：** 建立提供方中立的 BuilderAdapter，覆盖能力探测、启动、进展、工具结果、取消、会话接续和终态。首个待验收目标为 Codex CLI，配置允许选择模型和提供方；这项选择属于规划，不代表已有适配。实现必须读取实际 CLI/协议版本，不能以一个后端的行为推导另一个后端可用。
- **源码触点：** `src/composition/`、`src/providers/`、`src/process/`、`src/config/`；参考 `docs/client-configuration.md` 区分已有 MCP 客户端配置和新增主动构建适配。外部协议放在提供方层，共享应用服务不依赖后端专属事件格式。
- **依赖：** PW-01；启动、取消和恢复使用 PW-02；与 PW-04 约定构建输出和修复输入契约。
- **验收：** 对应 `PWA-04`、`PWA-05`、`PWA-06`；分别覆盖协议夹具与真实安装。真实记录包含可执行程序版本、使用的模型/后端、宿主、项目范围、开始/结束原因及产物 digest。测试退出码异常、事件不完整、无输出、断线、取消和会话恢复。
- **证据与完成标准：** 选定的真实 Agent 能在指定输出目录生成可检查产物，并将检查差异用于下一轮修正。Codex CLI 缺程序或有效授权时，该适配器记录为受阻；另一个明确选定的适配器可以独立验证，但不能静默切换并宣称 Codex 已通过。仅能列出模型、建立连接或输出文本不计完成。其它适配器可保留为计划，不列为真实可用。
- **未验边界：** 用户自己的 Agent 账户和凭据由其既有方式管理；项目文件不保存凭据或整个环境变量集合。工具可读范围和作用范围必须实际约束；声明“仅观察”不等于操作系统隔离。首个后端成功不证明多后端兼容。

### PW-04：复用检查器、证据与验收编排

**状态：未开始。阶段：M1。**

- **目标与范围：** 组合已有截图、浏览器场景、进程及重建评价器，形成可复核的检查运行。对多视口图像、行为场景、错误路径、存储和接口分别记录判定；独立预期结果及故障样例由验证侧维护。检查差异以结构化结果提供给 BuilderAdapter。
- **源码触点：** `src/domain/webScreenshot.ts`、`src/domain/browserCaptureComparison.ts`、`src/application/BrowserScenarioCaptureService.ts`、`src/domain/process/`、`src/application/ReconstructionObligationLedgerService.ts`、`src/application/ReconstructionCoverageService.ts`；按需复用 `src/application/environment/environmentCompare.ts`。
- **依赖：** PW-01；执行使用 PW-02；Builder 的修复反馈对接 PW-03，入口对接 PW-06。
- **验收：** 对应 `PWA-07` 至 `PWA-12`；多视口大小与采集条件固定并可追溯。动态区域排除必须记录原因和覆盖范围；尺寸错误、缺失截图、未知行为或不适用的证明不能得到通过。至少一个故意损坏的实现必须被独立检查识别。
- **证据与完成标准：** 检查结果绑定目标观察、场景/检查器版本、候选构建 digest 和当前义务版本；改变输入或产物后不能复用旧的通过结论。既有 ledger/coverage 负责闭合判定，执行器负责提供真实 proof，二者职责可检查。
- **未验边界：** 相似度只描述视觉维度；Agent 自己写的测试通过不能单独关闭功能义务。缺少实测或独立预期结果时保留未知；未观察的服务端逻辑和其它目标平台不计入覆盖。

### PW-05：网页或 H5 的真实闭环样例

**状态：未开始。阶段：M1 退出关口。**

- **目标与范围：** 选择仓库可分发、可本地运行的一个网页/H5 目标，覆盖页面布局、一个有状态交互、错误输入、持久化或恢复行为。目标和独立预期结果应固定，Builder 只获得当前研究范围允许的材料。通过真实 Agent 生成候选、检查、修正并保留最终项目。
- **源码触点：** `tests/fixtures/`、对应真实工作流验证脚本以及 PW-01～04 的生产入口；现有 `src/browser/`、`src/application/javascript/` 和 `src/application/environment/` 按实际样例调用。
- **依赖：** PW-02、PW-03、PW-04、PW-06 的最小切片可运行；所需浏览器和 Agent 已实际预检。
- **验收：** 对应 `PWA-09`、`PWA-10`、`PWA-12`、`PWA-13`；从干净目录执行，保留输入、产物、独立检查、错误识别和修正记录。执行至少一次中断后恢复；在新的工作目录重复运行以验证流程可复现，生成源码不要求逐字节相同。
- **证据与完成标准：** 输出可打开的实际候选、原始检查资料、项目状态和未决项。真实检查在声明的场景内通过，故障样例能失败，恢复后没有重复产生未授权作用，才能关闭本包。
- **未验边界：** 一个样例只证明该目标、Agent、宿主与场景组合。不推导任意网站、完整游戏、商业软件或任意服务端都能自动重建；无 Agent 运行条件时记录阻塞，继续验证可独立完成的检查器。

### PW-06：CLI/MCP 共享入口与工具元数据

**状态：未开始。阶段：M1。**

- **目标与范围：** 通过同一应用服务提供项目创建、读取、运行、检查、修正、恢复和取消所需入口。先确认现有工具是否已覆盖相同结果，再决定扩展或新增工具；元数据准确说明输入、作用、可用条件和输出。公开名称与参数在实现 PR 中确定，本文不发布可执行命令清单。

## 首个开发包：PW-01 的可执行接手步骤

下一次研发从 PW-01 开始；PW-02/03/04/06 可并行做代码定位和协议预检，不能先绕过项目身份、存储和执行边界搭建一条无法恢复的临时链路。

1. 查询实时 `main`、未合并 PR、审阅与 CI；保留已有开发分支和未提交变更，明确本次实现使用的 commit。读取根目录 `AGENTS.md` 与上述三份规划。
2. 复核 Evidence bundle、analysis snapshot、原子写入、资源归属的已有接口，列出可直接调用的函数以及确实缺少的项目语义。检查相邻实现，避免复制一套文件和完整性处理。
3. 在共享领域层实现最小项目 schema 与版本策略。先包含稳定身份、明确的目标/输出范围、两条状态轴、阶段、运行身份和 Evidence/检查引用；新增字段必须说明所有者、更新时机和作用。
4. 在应用层实现创建、读取和受控保存，复用现有文件所有权与 staged output。明确写入冲突、未知版本、损坏输入、迁移失败和中断后的可恢复状态。
5. 加入针对真实失效方式的验证：保存重读、旧版本处理、写入中断、并发冲突、证据/构建绑定变化和不完整项目读取。样例不含凭据或不可分发材料。
6. 执行相关领域/边界验证和当前提交所需静态检查；记录实际运行的命令、结果与限制。该包不需启动外部 Agent，也不应将其未运行写为已通过。
7. 提交可审阅的 PW-01 实现 PR，并更新验收矩阵对应记录。按实际审阅与 CI 结果修复，合并资格满足后进入 PW-02 及可并行的后续包，不重新编写总计划。

## 实施与验收记录规则

每个工作包的实现 PR 至少记录：源提交、改动范围、所满足的 `PW-*`/`PWA-*`、实际验证命令、宿主与依赖版本、产物/证据位置、失败原因和未验范围。状态在代码实现、审查与相应验收完成后更新，不能因计划文档存在而勾选完成。

工作包采用“未开始、进行中、受阻、已验收”记录研发进展；它与产品内的运行状态、验收状态是不同概念。产品状态的唯一字段定义在[设计方案](project-workflow-design.md)，实际支持范围的唯一验收记录在[验收矩阵](project-workflow-acceptance.md)。

验证从受改动边界开始：文档变更检查格式与引用；纯领域/存储变更运行相关边界测试；引入 Agent、浏览器、原生进程或新宿主时运行对应真实通道。只有当前提交满足所声明能力的检查，才更新该能力的资格，不反复运行与本包无关的全套外部验收。

涉及构建结果的每轮验证保留当时的输入、产物身份、检查器/场景版本和原始结论。代码改变后，旧 Evidence 可用于历史解释，不能自动证明新产物通过。无法独立观察的事实明确保持未知，补齐条件后继续原工作包。
